### How the matrix is built (so it can be extended)

- One abstract behavior per hook family, `<hook dir>/<Prefix>_SeMatrixBehavior.sol`, owns the ten §6 row tests (all `virtual`) and redeploys the hook through its real package with the fixture's face token and SE on every SE leg (M4). Rows are thin: `function _newFixture() internal override returns (SeMatrixFixture)`.
- One fixture per SE family, `test/foundry/spec/hooks/uniswap/v4/standardExchange/SeMatrix_<Family>Fixture.sol`, implements `SeMatrixFixture` (`faceToken`, `se`, `fund`, `hasPartialCase`, `limitCapacity`, `openCapacity`, `seBooked`, `armOperativeRevert`, `isAmm`, `otherToken`, plus `sweepsOnNextInvest`, `operativeRevertReachable`, `seedFaceUnits`). Fixtures deploy through the family's real package on that family's protocol fixture and prank the CREATE3 factory owner around facet deploys.
- Dependency failures are injected only on protocol stubs, hermetic ports, AMM pairs or the router with `vm.mockCall` / `vm.mockCallRevert`; never on the SE, hook, package or registry.
- Regenerate the evidence with `python3 scripts/hook_se_matrix_evidence.py <forge -vv log> docs/audits/apex-2026-09-17-evidence/hook-se-matrix.json docs/audits/apex-2026-09-17-evidence/hook-se-matrix-findings.json docs/audits/apex-2026-09-17-evidence/hook-se-matrix-finding-descriptions.json`. The findings map (`hook:family` to finding ids and blocked test names) and the descriptions (F1 to F7) are those two JSON files; edit them when a finding is fixed.
- Prank pitfall that cost a run: never place an external call (a fixture getter included) between `vm.prank` and its target; cache fixture values in `setUp`.
