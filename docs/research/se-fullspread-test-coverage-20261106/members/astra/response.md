## Assumptions

- The 2026-11-06 owner lock controls a named gap; otherwise the family obligation remains.
- `keep` below means preserve an already required family assertion. `add` means make an adopted remediation assertion or its explicit coverage cell appear in the plan. Neither word describes whether a test currently exists or passes.
- Descriptive row names below are proposed ledger names unless they are existing names quoted by FP or RPRD. They do not claim current source symbols.
- `c0` and `c1` mean the two caller-facing tokens in `vaultTokens()` order, substituting configured WETH for native currency. `S` means this vault's share.
- A row naming two directions, multiple bounds, or multiple functions requires each named case. A cell listing multiple files assigns the assertion to each listed file, not a choice of one file.
- Same-state comparisons use a genuinely identical pre-state. They compare execution return values and actual recipient effects, and assert rollback before any snapshot restore. Refund-word equality is not required: a preview assumes the declaration is available and does not read a funding balance. Output equality and output minima are still required.
- Production-first deployment, real PoolManager behavior, and accepted public bootstrap routes apply throughout. No mock, etch, storage injection, manufactured SUT shares, or added production booked getter is proposed.
