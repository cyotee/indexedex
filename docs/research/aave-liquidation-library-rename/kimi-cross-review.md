## 2. Corrections to peers (attributed)

**C1 — MiniMax's Option A bytecode/address claims are wrong; three of us + primary sources contradict them.** MiniMax §7/§10 assert that under filename-only rename "initcode is byte-for-byte stable (no Solidity source change → identical initcode → identical deployed library address)" and "No migration required… previously-deployed Spoke instances continue to call the same library." False: solc appends a metadata hash that includes source **filenames/paths** ("any change to the metadata might result in a change of the bytecode. This includes changes to a filename or path" — Solidity metadata docs; also in my original §3.6, Grok §Salt/address formulas item 2, Astra finding 4). Under Option A the library initcode changes (metadata + `compilationTarget`), so CREATE2 salt-0 and `AAVE_V3_LIBRARIES_BATCH` redeploys land at **new** addresses, and Pool/Spoke initcode changes too (new placeholder hash + metadata). Existing deployments keep working (embedded addresses), but any redeploy moves addresses. MiniMax's acceptance criteria §12.9 ("under Option A, getters return the same addresses as before on the same deployment set") is only true if nothing is redeployed — misleading as written.

**C2 — MiniMax's filename spelling and paths contradict the "suffix" instruction and its own framing.** MiniMax's Option A tables rename to `AaveV3LiquidationLogic.sol` / `AaveV4LiquidationLogic.sol` (a **prefix**) and place the v4 file at `.../libraries/libraries/AaveV4LiquidationLogic.sol` (wrong directory twice over; actual: `v4/spoke/libraries/`). Grok, Astra, and I all converged on the suffix form `LiquidationLogicAaveV3.sol` / `LiquidationLogicAaveV4.sol` in the existing directories. **Recommendation: adopt the suffix spelling** (`LiquidationLogicAaveV{3,4}.sol`); it keeps `LiquidationLogic*` grouping and matches the `LiquidationLogic.*.t.sol` test naming. MiniMax's §12.1 artifact-path criterion (`out/AaveV3LiquidationLogic.sol/AaveV3LiquidationLogic.json`) is doubly wrong under its own Option A: with the symbol unchanged the JSON stays `LiquidationLogic.json`, i.e. `out/LiquidationLogicAaveV3.sol/LiquidationLogic.json` (Grok §Inference has it right).

**C3 — MiniMax's "whichever compiles last overwrites" stated as bare fact is unproven as a general rule.** Astra (finding 3) and Grok (§"Artifact collision is real…") correctly demote it: Foundry compilers v0.19.6 `artifact_output/mod.rs` implements `conflict_free_output_file` with a per-pass taken-path set, shortest-path-component-first ordering, and cache reuse — disambiguation exists; overwrite is a stale/partial-build hazard, not a deterministic rule. My original reached the same conclusion independently from the two repos' `out/` states (I1). MiniMax also mischaracterizes the seed as existing "solely" for the LiquidationLogic collision; it is the compile root for 19 Crane implementations (my §4; Astra line 49; Grok §"What Artifact Seed actually is") and CLAUDE.md-protected regardless of this rename.

**C4 — Grok's IndexedEx-root `out/` table contradicts my direct measurement; I re-verified and stand by mine.** Grok's table (lines 70–71) lists IX-root `out/LiquidationLogic.sol/LiquidationLogic.json` as v4 (citing `DUST_LIQUIDATION_THRESHOLD`, `calculateLiquidationBonus`) while listing identical values for `lib/crane/out/`. My greps (run twice, including once after reading Grok): IX-root short slot contains `CLOSE_FACTOR_HF_THRESHOLD` and `executeLiquidationCall`, and does **not** contain `liquidateUser`, `DUST_LIQUIDATION_THRESHOLD`, or `calculateLiquidationBonus` → **v3.6 holds the IX short slot, and `out/logic/LiquidationLogic.sol/` is also v3.6; the v4 library artifact is absent from IX `out/`**. In `lib/crane/out/` I confirm Grok's rows (short = v4, `logic/` = v3.6). Likely Grok duplicated the crane-root observation into the IX rows (or the directory changed between passes — `out/` is live build state). Either way, the IX-root observation is the one that matches the in-repo "stolen artifact" comments, and it strengthens the overwrite-hazard evidence: the hazard is **demonstrated current state in IndexedEx `out/`**, not merely historical testimony.
