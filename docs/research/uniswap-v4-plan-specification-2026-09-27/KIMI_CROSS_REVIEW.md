## 2. Adjudicated arithmetic

- **CPPlace (adopted, Astra's form):** `target_i = floor((D_i+F_i)·p/(1e18+p))`; `budget_i = D_i+F_i−target_i`; `LiquidityAmounts.getLiquidityForAmounts` at current price/fixed ticks; add-side liquidity rounding stencil `max(L*−1, L0)` highest-affordable; removal = direct difference with exact rounded proceeds. **Certificate:** the fully evaluated terminal state (user leg + fee collect + placement) passes both thresholds, or makes strict progress under §3 with no omitted payout; a result needing a holder swap for useful progress is outside CPPlace (deferred/truthful no-op; public rebalance repairs). No solver is reachable from the exact-output call graph.
- **Metrics (D21, adopted from Astra; mine were structurally identical):** per-unit requirements at current price `d0 = 1/u − 1/√b`, `d1 = u − √a` evaluated as rational Q96 coefficients (never materialized unit amounts); `X = T0·d1`, `Y = T1·d0`; `rho = |X−Y|/max(X,Y)` (FullMath cross-products; `rho = 0` iff `X = Y = 0`; one-sided boundary = placement-only on the active leg). Sufficient iff `rho ≤ 1/10000`. Sleeve: deadband `max(absoluteFloor_i, 5%·targetFree_i)`; `sigma = max_i(max(|F_i−target_i| − band_i, 0)/max(T_i,1))`; stop when `rho ≤ 1 bp` and `sigma = 0`.
- **Progress ordering (adopted):** lexicographic `(max(rho−1bp,0), sigma)`, strict decrease after ALL fees and final placement; placement-first; tie-break: no swap < lower turnover < smaller liquidity change; truthful no-op otherwise (D21:301-302).
- **Depositor ε (§7):** `sharesOut·B_i·10000 ≥ S·C_i·9999` both legs via full-width products; no dust exception; distinct from rho.
- **Impact (D20):** `max(sa,sb)²·1e18 ≤ min(sa,sb)²·(1e18+limitWad)` via mulDiv — price, not sqrt-price; per leg; overflow fails the cap.
- **Shortfall (10 bp):** measured output ≥ `ceil(feeInclusiveQuote·9990/10000)`; reference quote must match the actual fill size; LP+protocol+Pons charges included exactly once.
- **Constants:** fixed per family, no setters (D25): 25/50/10/1 bp; sleeve `p` stays the live oracle parameter; selector-identical liquid-reserve interface across families preserves the usage-fee type id and 20% cascade (interface ids are selector-XORs — name changes do not change them).
