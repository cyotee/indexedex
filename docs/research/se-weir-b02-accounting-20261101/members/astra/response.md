# Question and targets

Does WeirVaults' own accounting prevent the B-02 losses, or can a caller-moved pool price still put a loss on other holders?

**Answer:** Weir prevents the specific whole-opposing-balance redemption dump by swapping only the withdrawn net. It does not protect shared reinvestment from a displaced live price. Its liquidity-denominated shares protect old deployed liquidity from dilution by a new caller-funded deposit, but do not reimburse holders for losses on their own idle/fee inventory when that inventory is compounded. Raw Weir has no automatic post-withdraw placement; nevertheless, a later permissionless compound can place at the withdrawal's moved price if there is a usable pair, including opposite-side fees generated by that withdrawal swap. A no-fee, one-sided-idle counterexample does not mint and must not be presented as a loss.

## Amount formulas and the accounting identity

**Source observation.** For square-root bounds `a < s < b`, LA:15-39 and LA:43-65 give, ignoring integer rounding and Q96 scaling:

```text
L0 = amount0 * s * b / (b - s)
L1 = amount1 / (s - a)
L  = min(L0, L1)
amount0(L,s) = L * (1/s - 1/b)
amount1(L,s) = L * (s - a)
```

**Model choice.** The executed script uses the explicitly permitted infinite-range limit, `a -> 0`, `b -> infinity`, rather than evaluating usable ticks:

```text
dL = min(A0 * s, A1 / s)
placed0 = dL / s
placed1 = dL * s
```

At `P0 = 1`, `s0 = 1`, after the pool price returns:

```text
recovered0 = recovered1 = dL
placement shortfall at P0
  = placed0 + placed1 - recovered0 - recovered1
  = dL * (s + 1/s - 2)
  = dL * (s - 1)^2 / s
```

This is exactly the audit's full-range approximation for the chosen continuous infinite-range fixture. For fixed finite bounds containing both prices, the bound terms also cancel in this value difference: `dL * (s - s0)^2 / s`. The finite-range sizing of `dL` and integer rounding still differ; those were not simulated.

**Inference independent of the swap approximation.** If the placed inventory already belongs to the vault and shares do not change, a holder owning fraction `h` bears `h` times that shortfall. Adding liquidity to the internal counter does not create compensation: W:373 adds `dL`, W:378-379 removes the consumed idle, and W:290-292 later redeems each holder's fraction of those assets. No swap-price model is needed to establish whose assets were placed, who owns the resulting position, or the fact that W:360 sizes it at current spot.

Conversely, with no pre-existing idle, a caller depositing `dL` into existing `L,S` receives `m = dL*S/L`. Old holders' liquidity claim afterward is:

```text
S / (S + m) * (L + dL) = L
```

That preserves old deployed liquidity. The caller owns the added liquidity and receives unused deposit input back; the caller bears the displacement loss on that new input. This is a genuine protection, but it is not a protection for inventory compounded on behalf of existing holders.

# Assumptions

2. All positions use the infinite-range limit above. Tokens and liquidity are continuous normalized units. For interpreting source dust/floors, the examples can be understood as large token amounts relative to one raw unit. The script does not claim Q96, uint128, floor-division, two-unit-cushion, or genesis-floor bit fidelity.
3. The primary external-compound example has existing `L = 1000`, `S = 1000`, and an owned reinvestment budget `(100,100)`. A source-compatible composition is booked idle0 of 100 plus net harvested fee1 of 100; at the source's default 5% cut, gross harvested fee1 would be `100/0.95`. The comparison starts after that cut, so the reported loss is placement loss, not the performance fee. This does not assume an ordinary Weir deposit leaves its unused input behind: W:182-183 refunds it.
4. The compound caller holds 10% of the existing supply in the allocation example. A caller holding no shares can also invoke compound; such a caller bears none of the vault's placement loss through share ownership. This is not a claim that its external price push is free.
5. Swap legs use a **constant-product approximation** to a fixed-liquidity, full-range pool: virtual reserves `x = Q/s`, `y = Q*s`, with `x*y = Q^2`. This approximates actual V4 execution with no tick crossings or hooks. The code labels it; no claim is made that arbitrary V4 pools have constant liquidity.
6. Fee-free swaps isolate inventory ownership. The additional self-moved case assumes a 0.3% input swap fee, no protocol fee, and accrual to the staying position in proportion to its active liquidity. This is an explicit pool fixture, not a Weir-imposed fee. Only those harvested fees pay Weir's actual default 5% performance fee.
7. Returns to `P0` are valuation benchmarks for the liquidity amounts. Push/restoration capital costs, restoration-generated fees, gas, and attacker net profit are not simulated. In particular, a fee-funded placement shortfall does not imply staying holders lost money overall relative to before earning those fees.
8. The 024-shaped comparison closes the whole position and distributes realized token0 proceeds pro rata. This is an explicit comparison convention, not a reconstruction of the deleted Wings liquidation quote, core/wing allocation, or exact payout entitlement. Both branches start with the same vault inventory, pool liquidity and exit fraction, and use the same nonbinding absolute upward limit from W:422.

## Case 1: external push followed by placement

At `P'=2`, the owned `(100,100)` budget places `(50,100)` and recovers `(70.710678119,70.710678119)` at `P0`. The placement shortfall is **8.578643763** token1-equivalent units. Remaining idle0 is 50. At `P'=4`, it places `(25,100)`, recovers `(50,50)`, and loses **25**, with 75 idle0 left.

Existing other holders owning 90% bear **7.720779386** and **22.5** respectively. The 10%-holding caller bears **0.857864376** and **2.5** through its shares. Compound issues no new shares, so there is no entry-price adjustment that charges the entire loss to the invoker.

Pure one-sided idle `(100,0)` or `(0,100)` produces **zero liquidity and zero placement loss** at both interior prices. `_compound` does not balance it. This is a material limitation of the exposure, not evidence of a price guard.

For the separate caller-funded deposit with zero old idle, `m = dL*S/L` mints **70.710678119** or **50** new shares. Old holders lose **zero** of their original liquidity value at `P0`; the depositor bears the placement loss and receives its unused 50 or 75 token0 back.

There is a further accounting qualification, not a proposed new blocker: if the old owned budget is compounded first and leaves 50 or 75 idle0, a following depositor is priced against `L = 1070.710678119` or `1050`, not that idle. It receives **66.040882531** or **47.619047619** shares and thereby acquires **3.097483577** or **3.409090909** of the old idle. W:269 excludes idle, while W:291-292 includes it in redemption. Thus a claim of complete old-holder value isolation would be too broad even though the liquidity-only identity holds.

## Case 2: self-moved price followed by a separate compound

The source-faithful order matters. Raw Weir does **not** automatically run a trailing placement after the withdrawal swap. It compounds first, removes the withdrawing fraction, swaps only that withdrawn net, and returns.

The executed fixture starts with `L=800`, `S=1000`, idle `(400,0)`, and a 60% exit to token0. Pre-withdraw compound has no token1 to pair with idle0 and adds zero liquidity. Withdrawal removes 480 liquidity, 240 idle0, and swaps **480 token1**, all from the exiting slice. It leaves `L=320` and idle `(160,0)` for stayers. Different explicitly reported pool depths make that exact withdrawn-net swap finish at 2 or 4.

- With no swap fees, a subsequent compound still has `(160,0)`, adds **zero**, and has **zero** placement loss. Fabricating a two-sided idle bag after pre-compounding would have produced a false proof.
- With a 0.3% swap fee, the staying position earns the opposite token during the zap. After Weir's default cut, its fee1 is **0.378899467** at the 2x fixture or **0.914744233** at the 4x fixture. A following permissionless compound pairs that fee with remaining idle0 at the zap-moved live price.
- Those later placements lose **0.032504436** and **0.228686058**, respectively, versus retaining the placed token amounts until return to `P0`. All that placement loss belongs to the remaining holders; the exiter's shares were already removed at W:296.

This proves a narrower, source-faithful result: raw Weir removes the automatic trailing call and limits inventory available for it, but does not ensure that a later compound cannot use a self-moved price. It is not a reproduction of the audit's exact same-call Route I, and the fee-bearing examples remain fee gains net of a placement drag, not a demonstrated profitable attack.

The no-approximation distinction is the quantity and ownership: W:290-311 segregates the exiting fraction and W:314 sells that fraction's net1. In the 024 shape, the input includes the stayers' opposing inventory. Changing the absolute price limit is not what distinguishes these two cases.

It establishes the absence of the specific direct liquidation of stayers' opposing inventory in `_withdraw`. The audit's design note at A:1669 distinguishes fair-mark losses from liquidation-value entitlements and lowers the back-run-only severity; these simulated `P0` marks do not override that qualification.

## Case 4: half-excess `_balance`

From W:392-403, in continuous units:

```text
if A0 * P > A1: swap token0 amount (A0 - A1/P) / 2
if A1 > A0 * P: swap token1 amount (A1 - A0*P) / 2
```

For caller input `(100,100)` and pool liquidity 1000, the first branch sells **25** token0 at initial `P=2`, or **37.5** at `P=4`. The modeled swaps move the price to **1.865740079** or **3.461330449**. W:255 then reads that new price for placement.

At those post-swap prices, the new positions have placement shortfalls **10.042361369** and **46.275013521** when valued back at `P0`. The swap itself sold token0 at an elevated price and has positive `P0` mark gains; after combining both legs and refunds, caller net changes are **+13.250237427** and **+55.759870200**. These are not attacker round-trip profits because the external price push and restoration are not funded in this experiment.

Half-excess is a ratio-matching heuristic based on current spot, not an exact post-swap ratio solution: the script reports token1 excesses **8.362092890** and **23.201730665** after the swap. Unused input is returned, not forced into shared idle. With zero pre-existing idle, old deployed-liquidity claims remain unchanged by share issuance. `_balance` neither checks `P0` nor runs on shared compound inventory, so it does not solve external-push compounding loss.

# Conclusions

1. **External-push shared placement: not resolved by Weir.** Observation: W:355-367 spends the holders' net fees and idle using current slot0; W:373 adds liquidity without shares. Inference and executed proof: when a usable pair is deployed at the pushed price, the return-price shortfall is borne by existing holders pro rata. W:378-379 leaves the reduced idle balance in their book, and W:290-292 gives them only their fraction of the resulting liquidity and idle. The invoker does not pay the other holders' shortfall. Pure one-sided idle is not deployed, and caller-funded entry is a distinct ownership case.
2. **Self-moved trailing placement: the exact automatic trailing call is absent, but the price risk is not generally resolved.** Observation: W:235 compounds before withdrawal, and W:324 returns without another compound. Inference: that removes the old audit's automatic same-call placement from raw Weir. However, W:207 permits a later call and W:360 then uses the self-moved live price. The executed fee-bearing examples supply a usable pair from remaining idle0 and the zap's earned fee1. The exiting shares are already gone at W:296, so the later placement shortfall belongs to stayers. A following compound with only one-sided idle and no fees does not mint. FS-OWN-12's separate trailing sleeve behavior must not be erased by substituting the raw-Weir call sequence.
3. **Whole-balance redemption dump: the specific 024 quantity error is absent from Weir's withdrawal.** W:290-311 isolates the exiting slice, and W:314/318 swaps only its net unwanted currency. It does not close all liquidity merely to fund a partial withdrawal or pass the whole opposing balance to `_swap`. The unchanged absolute limit still allows price impact on the exiting slice, but does not by itself imply sale of the staying holders' inventory.
4. **Internal accounting separates ownership; it does not certify price.** W:269 protects existing deployed-liquidity claims during a new deposit. W:391-410 operates on that caller's input. Neither rule measures a shared placement against an earlier pool price. Idle's exclusion from issuance but inclusion in withdrawal is also a reason not to generalize the liquidity-only protection into complete value preservation.
5. **Selecting Weir is not a new accounting decision.** FS-MONEY-01 already copies the liquidity denominator, compound-before-money order, reinvestment plus idle, proportional withdrawal, and absolute entry limit. FS-OWN-12 adds sleeve movement; FS-OWN-14 changes no-fee behavior; FS-OWN-15 specifies deployed-first redemption. These existing sentences, and their differences from raw Weir, remain the comparison. This response neither locks B-02 nor asserts the owner accepted a replacement.
