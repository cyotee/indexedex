## Question

Write an implementable requirements specification for IndexedEx's own Crane diamond vault that earns trading fees on one homogeneous Uniswap V4 position, mints shares from a price-free liquidity-unit claim, and can be valued and exited in one target token. Settle the receipt shape. Do not reconstruct any third-party implementation.

## Proposed text

This specification is a proposal for a new vault. It is not implementation authorization. It does not change any existing Wings vault. It does not redefine `getRate` as NAV. It does not assume an independent price. No project test was run. Equations below are design statements except where a sentence says the coordinator re-read an existing function.

Third-party pair-token source was not an input. A later agent must implement this file and the IndexedEx paths it cites. It must not open that excluded source to fill a gap.

### What the vault is

One Crane diamond. One Uniswap V4 pool. One tick range. One position salt. The diamond proxy is the position owner and the address the pool manager calls back. The only transferable claim is the diamond's ERC-20 share. The liquidity-unit receipt is an internal ledger. It is not a second token.

Deposited capital funds that one position. Holders earn that position's trading fees in the two pool currencies. Exit pays one configured target currency. The other currency from the redeemed slice is sold through the same pool. That sale is not a fix for quote manipulation. The mint does not use it.

### Terms

| Symbol | Meaning |
| --- | --- |
| `U` | Booked liquidity of the one position. Not a sum across ranges. Not a token balance. Not a fee balance. |
| `S` | Share supply. Fee recognition must not mint shares into `S`. |
| `d` | Stored conversion offset. Both directions use it. It is not derived from a price. |
| `uReceived` | Liquidity units the position actually gained in this call. Not a pre-trade quote. |
| `Q` | Fee-index scale. Fixed at initialization. Not a price. |
| `feePerShare_i` | Cumulative attributed fee of currency `i` per share, in `Q` units. |
| `debt_i(account)` | That account's settled `floor(balance * feePerShare_i / Q)`. |
| `unclaimed_i(account)` | Fee tokens of currency `i` already attributed to the account and not yet paid. |
| `dust_i` | Collected fee tokens of currency `i` not attributed to any share. Not holder property. |

Share decimals are 18. `d` is 9. Both are stored at initialization. The coordinator re-read those two literals in `UniswapV2StandardExchangeDFPkg.initAccount`. They are adopted so this conversion matches the re-read converter. They are not a price input.

One whole share is `10^18`. One whole target token is `10^dT`, where `dT` is the target token's decimals.

### Decision 1. Receipt shape

Chosen rule. One homogeneous receipt for one `(pool, range, salt)`.

```text
shares = floor(uReceived * (S + 10^d) / (U_before + 1))
```

`U_before` and `S` exclude this call's new liquidity and new shares. Received units are the numerator. They are not added to the denominator.

The coordinator re-read `BetterMath._convertToShares`. With floor rounding it is `assets.mulDiv(totalShares + 10**decimalOffset, reserve + 1, Floor)`. The coordinator re-read the exact-in LP branch in `UniswapV2StandardExchangeInTarget`: after the fee-share step, it converts `amountIn` against `reserveBefore`, not against `reserveBefore + amountIn`. An OutTarget comment that puts `lpReceived` in the denominator is not the executed mint. This specification adopts the executed form. It does not adopt that comment.

The V2 fee-share mint that runs before that conversion is not adopted. `S` in this equation is not increased by a reserve-dependent fee-share mint.

Rejected alternative. Astra's componentwise basket: one liquidity component plus two fee-currency components, with the depositor funding each in kind. That join can be price-free. It is a different design from the single-denominator liquidity-unit mint this question asked to settle. Old-fee capture, which that basket prevents by funding, is prevented here by Decision 3. The basket is dissent, not a second mode.

Rejected alternative. Kimi's compounding of fee tokens into extra liquidity before the mint. That changes `U` by a composition at the current tick and can require a same-pool swap. Fee value stays outside `U`.

Evidence class. The equation is a source observation of BetterMath and the InTarget call. Choosing this receipt over the basket is a proposal. The wrap report left both shapes open; that openness is a source observation of the report, not agreement with this choice.

### Decision 2. One outer share, one range

Chosen rule. Initialization binds pool key, tickLower, tickUpper, salt, and target currency. No later call adds a second range, changes the salt, or adds another position's liquidity into `U`. A second range is a different vault. Rebalancing is out of this specification.

One outer share owns this receipt and the fee-accumulator claim in Decision 3. It does not own another range, an idle donation, or a right to be minted against a liquidation quote.

Rejected alternative. Summing liquidity across ranges into one `U`. Already rejected by the wrap report. Equal liquidity integers in two ranges are not the same claim.

Evidence class. The sum rejection is a source observation of the wrap report. The one-position binding is a proposal all four responses made.

### Decision 3. Fees

Chosen rule. Trading fees increase holder value in native token units through a per-share accumulator. They do not change `U` or `S`. They are not marked at a square-root price, a TWAP, or a target quote.

When. Every deposit, exit, and permissionless `sync` collects newly owed fees for this position before `S` or `U` changes. `getRate` applies the same pending delta in the preview and writes nothing. A bare token transfer is not recognition.

Who receives fees that existed before a deposit. Only shares already in `S` when that fee growth accrued. New shares start with no claim on the pre-sync accumulator.

With `S > 0`:

```text
attributed_i = floor(delta_i * Q / S)
feePerShare_i += attributed_i
dust_i += delta_i - floor(attributed_i * S / Q)
```

`delta_i` is the newly collected amount of currency `i` owed to the pre-change liquidity and not already in `feePerShare_i`. Dust is not folded back into a later `delta`. Dust is not paid to a new depositor. Dust is not swap input.

If `S = 0`, collected tokens are dust. They are not a mint bonus for the first depositor.

Before a balance change, settle that account:

```text
owed_i = floor(balance * feePerShare_i / Q) - debt_i
unclaimed_i += owed_i
debt_i = floor(balance * feePerShare_i / Q)
```

Then change the balance and set `debt_i = floor(newBalance * feePerShare_i / Q)`. A mint adds shares and does not increase `unclaimed`. A transfer settles both sides. A transfer does not change `S`, `U`, or `feePerShare`.

An exit, after the pre-burn settle, pays `floor(unclaimed_i * sharesBurned / balanceBefore)` of each currency and reduces `unclaimed_i` by that amount. Tokens the pool pays because liquidity was removed fund that payment. They are not a second payment. They are not new liquidity.

No usage-fee share is in this specification. A later authorization could take a fraction of collected fee tokens in kind before they enter `delta_i`. It must not do that by minting shares from a price. This specification does not add that take.

Rejected alternatives. The V2 `_calcAndMintVaultFee` path. A spot mark of uncollected fees in the issuance denominator. Compounding fees into `U` before the mint. Astra's in-kind fee funding, retained as dissent under Decision 1.

Evidence class. The accumulator equations are a proposal, taken from Grok's and MiniMax's responses and checked against the fee-vault report's uncredited-fee boundary. That boundary is a source observation of the report: leaving owed fees uncredited so the next depositor can take them on exit is forbidden. The V2 fee-share mint is a source observation of `UniswapV2StandardExchangeCommon` and is not adopted. Pool fee-growth field names were not re-read by the coordinator. The implementer must collect what the pool owes this position, in token units, and must test Decision 8's old-fee cases. A wrong pool field is an implementation defect, not a license to invent a price.

### Decision 4. Single-token entry

Chosen rule. This specification has no vault-initiated swap on entry.

Entry pulls the two pool currencies, adds liquidity to the one position, refunds amounts that do not become liquidity, and mints with Decision 1. Either amount may be zero when the current tick leaves that side unused. If the add produces no liquidity, the call reverts. Refunded tokens are not booked as fees, as `U`, or as a claim on existing liquidity.

The current tick may change how many liquidity units a token amount produces. That changes `uReceived`. It does not enter the denominator.

A same-pool swap by some other contract, before this call, is outside the vault. The vault must not itself swap on deposit.

Kimi and MiniMax include a single-token zap as a separate route and say it is not the share-pricing protection. That route is not in this specification. If a later specification adds it, the mint equation stays Decision 1, the swap input is not `U`, and the text must not claim that a deposit swap plus the exit sale closes the swap-capture result. This file does not add it.

Evidence class. Exclusion is a proposal. Grok and Astra excluded the swap. Kimi and MiniMax included it with an explicit non-claim. The swap-capture conclusion that a deposit swap plus an exit swap does not close the extraction result is a source observation of that report, not re-executed here.

### Decision 5. Single-token exit

Chosen rule. Exit burns shares, removes only that slice's liquidity, and sells only the opposing currency from that slice plus that slice's opposing fee claim.

After the fee sync, and before the burn:

```text
uOut = floor(shares * (U + 1) / (S + 10^d))
```

The coordinator re-read `BetterMath._convertToAssets`. With floor rounding it is `shares.mulDiv(reserve + 1, totalShares + 10**decimalOffset, Floor)`. This is that function. It is not `floor(shares * quote / S)`. It is not a whole-book liquidation.

The call removes exactly `uOut`. It does not remove the rest of the position. It pays the burned shares' fee claim from Decision 3 once. It swaps exactly the opposing amount from that removal plus the opposing amount of that fee claim. The swap input is that sum. It does not include remaining opposing inventory, other holders' fee tokens, dust, or donated balances. It does not borrow opposing. It does not remove extra liquidity to improve the fill.

The redeemer receives target from the removal, the target fee claim, and the sale proceeds. Exact-target-out is not a route. The caller supplies `minTargetOut`. If the sale cannot complete, or the target paid is below `minTargetOut`, the whole call reverts. Unfilled opposing is not paid as target. Target is not taken from other holders. No partial burn, removal, or fee payment remains.

A separate in-kind route may pay both currencies and skip the sale. It is not the target-token route. It must not be used to complete a failed target exit.

Evidence class. The `uOut` equation is a source observation of BetterMath. The slice-only sale matches the V2 `_withdrawSwapDirect` limit as Grok reported it; the coordinator did not re-open that function on this pass, so that sentence stays a member observation. The atomic revert is a proposal. All four responses required it. The wrap report's failed-sale rule was a proposal, not a V2 observation.

### Decision 6. Diamond boundary

Chosen rule. The diamond proxy calls `unlock`. The callback selector is on a facet of that same diamond, so the callback runs by delegatecall and `address(this)` is the diamond. No other address may be the unlock caller, the callback target, or the position owner.

The diamond owns the position, `U`, `S`, the fee accumulator, dust, the target identity, and in-flight removal or fee proceeds. In-flight proceeds are paid, refunded, or booked to fee claims before the callback returns. They do not become `U`. At the start and end of a deposit or exit, position liquidity equals `U`. Donated currency is not holder property and is not swap input.

A facet may hold bytecode immutables that are identical for every vault using that facet, such as a chain-singleton pool manager. It must not store the position key, `U`, `S`, the fee accumulator, dust, or the target in facet-address storage. Those live in a diamond repo slot. `PkgInit` and `PkgArgs` live on the package interface, not on the package contract. `unlockCallback` is listed in `facetFuncs`. Direct calls to the facet implementation cannot own a position. The callback reverts unless `msg.sender` is the configured pool manager and an entry point armed the in-flight flag. Sender check alone is not enough. The flag alone is not enough.

Deployment follows existing Crane rules: facets through CREATE3, one DFPkg, registration in the IndexedEx manager vault registry, reuse of `DiamondPackageCallBackFactory`. This specification does not authorize that deployment.

Rejected alternatives. An external clone or position-manager NFT as the owner. A helper that calls `unlock` while the diamond claims the position. Copied third-party control flow.

Evidence class. Diamond proxy as callback target is an inference from Crane delegatecall, adopted from all four responses. The coordinator did not execute a PoolManager trace. The Crane storage and package rules are source observations of the architecture skill as the members reported them. The coordinator did not re-open that skill on this pass.

### Decision 7. `getRate`

Chosen rule. `getRate` is the normalized preview of withdrawing one whole share and selling that slice. It writes nothing. It is not an issuance input. It is not `liquidateAll(book) / S`. It is not a NAV mark. This council does not redefine it.

Preview, at current pool state:

```text
uOut = floor(10^18 * (U + 1) / (S + 10^d))
```

Apply the pending fee delta to a preview copy of `feePerShare`. Take one whole share's fee claim from that preview. Preview removal of `uOut`. Preview an exact-in sale of that slice's opposing removal plus its opposing fee claim. Use the same rounding direction as execution, against the redeemer.

```text
q = targetFromRemoval + targetFeeClaim + saleProceeds
getRate = floor(q * 10^18 / 10^dT)
```

`getRate` reverts when `S = 0`, when `uOut = 0`, when the removal cannot be previewed, when the sale cannot be quoted, or when `q = 0`. It does not return a synthetic constant. It does not return principal and ignore a missing sale.

A same-pool tick can change `q`, because removal composition and the sale both depend on pool state. That movement is the preview. It is not permission to put the tick into Decision 1.

A hook that holds this share values it as raw balance, or as balance times a configured rate provider. It does not derive a rate by calling this vault's issuance preview. If this share is a buffered leg, the provider must fail closed on revert, short return, or zero. This specification does not claim that provider is manipulation-proof.

Evidence class. The conversion is the re-read asset function. The WAD shape is a source observation of the held-reserve rule as members reported it. The revert set is a proposal. The coordinator did not re-open `INDEXEDEX_AGENT_LAW.md` on this pass.

### Decision 8. Invariants a later agent must test

These are requirements for a later authorized test pass. This run does not authorize writing or running them.

1. After a successful deposit, shares minted equal `floor(uReceived * (S_before + 10^d) / (U_before + 1))`. `S_before` and `U_before` exclude the new shares and the new liquidity. No fee-share mint sits between them.
2. Received liquidity is not in the denominator. A denominator of `U_before + uReceived + 1`, a square-root price, a same-pool TWAP, a liquidation quote, an idle balance, or a fee balance is a defect.
3. Given the same `uReceived`, `S_before`, and `U_before`, a spot move does not change shares minted. The same move may change how many liquidity units a token amount produces, and may change `getRate`.
4. After initialization, pool key, ticks, salt, and target are unchanged. `U` contains no other range.
5. `U` increases only by `uReceived` of a successful deposit and decreases only by `uOut` of a successful exit. At the start and end of those calls, position liquidity equals `U`. A bare transfer does not change `U`, `S`, or `feePerShare`. A mismatch reverts.
6. After fees accrue and another account deposits, the new holder's claim on that already-accrued fee is zero. Dust is not paid to the new holder. The fee sync itself does not change `S` or `U`.
7. The exit swap input equals the opposing amount from removing `uOut` plus the opposing fee claim of the burned shares. Remaining liquidity, other holders' fee claims, donations, and dust are not inputs.
8. If the sale cannot complete or `minTargetOut` is not met, state is unchanged.
9. `getRate` equals the same preview executed for one whole share, after the specified normalization. It reverts on every Decision 7 case and never returns a constant substitute.
10. `unlockCallback` runs only when `msg.sender` is the pool manager and an entry point armed the flag. The position owner is the diamond. A direct facet-implementation call cannot move the position.
11. A transfer settles both fee claims and does not change `S` or `U`.
12. A one-share round trip is not profitable. Mint floors. Redeem floors.

### Normative deposit sequence

1. Sync fees under Decision 3.
2. Settle the recipient if that account already has shares.
3. Pull both currencies. Refund is allowed. No vault swap.
4. Add liquidity. Read `uReceived` from the position's liquidity increase.
5. If `uReceived` is zero, revert.
6. Mint `floor(uReceived * (S + 10^d) / (U_before + 1))` to the recipient.
7. Set the recipient's `debt` from the post-mint balance.
8. Set `U` to the position's liquidity. If they differ, revert.

### Normative exit sequence

1. Sync fees.
2. Settle the holder.
3. Compute `uOut`. If it is zero, revert.
4. Burn the shares. Reduce `unclaimed` by the burned shares' claim.
5. Remove exactly `uOut`.
6. Swap only that slice's opposing removal plus its opposing fee claim.
7. Pay target. If below `minTargetOut`, revert the whole call.
8. Set `U` to the remaining position liquidity.

### What this does not deliver

It does not make `getRate` independent of the pool. It does not close execution-price exposure on the exit sale. It does not let a depositor enter with one token through this vault. It does not hold more than one range. It does not replace the existing Wings vault. It does not grant a right to copy excluded third-party source if an implementer gets stuck.
