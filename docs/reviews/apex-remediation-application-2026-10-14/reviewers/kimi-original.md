### Finding 1 — REQ-C04 / Stage-1 REQ-01 (OD-08): hook preview of zero still books instead of rolling back

- **Severity:** Medium (per the controlling confirmation PRD and the Stage-1 REQ-01 severity; current code does not change the impact class — a caught soft zero still continues the parent operation and commits a holder-reserve update; no demonstrated loss claimed).
- **File and line:** `contracts/vaults/detf/protocols/dexes/uniswap/v4/detf/UniswapV4DetfCommon.sol:605` and `:615` (both hook-preview branches `return 0`), `:565` and `:590` (`if (lpOut_ == 0) break;` in both join loops), `:543-545` (terminal `_updateReserve` booking reachable after a hook zero), comments at `:548-549` and `:612-613`.
- **Remediation ID:** REQ-C04 (origin Stage-1 REQ-01 / OD-08).
- **Intended behavior (controlling text, closely paraphrased):** "A hook preview of `0`, or a hook join revert, rolls the parent transaction back. It does not book a new holder reserve. It does not continue into another join mode." Required repair item 1: "At both hook-preview checks in `_entryJoinResidualAtomic`, a quote of `0` reverts. It does not return `0`." Item 4: "Remove the loop branches that treat a zero LP return from this hook join as ordinary no-progress." Item 5: rewrite the named comments. Item 6: rewrite the tests that expect continuation or booking after a hook preview of zero.
- **Broken requirement or invariant:** OD-08's rollback rule. `_entryJoinResidualAtomic` still translates a hook preview of `0` into `return 0` at both branches; both loops still treat `lpOut_ == 0` as ordinary no-progress and break; `_tryJoinResidual` then reaches the terminal `_updateReserve` at `:545`, booking the full local balance. A proportional hook preview of `0` still falls through to the single-asset mode (`_joinResidualCapped` is tried after `_joinResidualUnbalanced` in `_tryJoinResidual` at `:531-541`). The comments at `:548-549` ("A zero complete-route quote retains the booked remainder") and `:612-613` ("a one-sided proportional join can be unsupported") still teach the withdrawn shape.
- **Impact class:** Error propagation and residual accounting. A soft zero commits a holder-reserve update instead of reverting the parent.
- **Fix direction:** Make both hook-preview zero checks revert (existing `ResidualJoinUnavailable` or a dedicated error; no new `catch`); remove the `lpOut_ == 0` loop-break branches once unreachable; keep the terminal reserve sync at `:543-545` but ensure the hook-zero path reverts before it; rewrite the named comments; rewrite the tests named below to expect parent rollback and no new reserve update.
- **Confidence:** High.
- **Observed fact vs inference:** Fact — the cited lines read as described; the revert is absent. Fact — the tests still expect continuation (see Finding 2). Inference — none needed; the PRD's required repair text matches the missing code exactly.

### Finding 3 — RC-01 legacy V4: yield settlement routed through a delegatecall to the execution delegate, not the inherited internal function

- **Severity:** Low. The confirmation PRD kept REQ-C01 at Medium for the unmet self-call prohibition; that core law is now satisfied on legacy V4 (no external call or delegatecall to `address(this)`, explicit holder, both burn sites use the holder). I lower the severity because the remaining deviation is repair-shape conformance, not the forbidden caller-identity mechanism. No unauthorized payout path was established: the delegate's holder-bearing entrypoint reverts on direct call (`DelegateCallRequired`, `UniswapV4StandardExchangeInExecutionDelegate.sol:9,16`) and its selector is not exported by the one facet that inherits it (`UniswapV4StandardExchangeInFacet.sol:25-30` exports only `exchangeIn`, `unlockCallback`, and the SY execution selectors).
- **File and line:** `contracts/protocols/dexes/uniswap/v4/UniswapV4StandardYieldExecutionTarget.sol:26-36` (`_settleNamedHolder` delegatecalls `UNISWAP_V4_STANDARD_EXCHANGE_IN_EXECUTION_DELEGATE` with `executeNamedHolderRedemption(address,uint256,uint256,address,address)`); `contracts/protocols/dexes/uniswap/v4/UniswapV4StandardExchangeInExecutionDelegate.sol:13-18` (the new holder-bearing external entrypoint).
- **Remediation ID:** RC-01 (controlling PRD + plan, 2026-10-11).
- **Intended behavior (controlling text):** PRD law: "delegatecall to a different execution-delegate contract is not a call to self. It is also not the required path when the facet already inherits the settlement function. The required path is an internal call that passes the holder." Plan Step 2: "`_redeemVaultHeld` ... calls the inherited function directly." Plan Done-when: "Both yield facets call the inherited exact-input settlement and pass the holder." Plan build gate: "do not move the yield path onto a delegate, to get under the limit."
- **Broken requirement or invariant:** `UniswapV4StandardYieldExecutionTarget` inherits `_executeZapOutExactIn` through `UniswapV4StandardExchangeInTarget` → `UniswapV4StandardExchangeInBase` (`:146-184`), exactly like V3 FullSpread, which does call it internally (`UniswapV3FullSpreadStandardYieldExecutionTarget.sol:26-30`). Legacy V4 instead introduced a new external delegate entrypoint that takes a holder argument — the same surface class the plan's out-of-scope rejected for the public wrapper ("it would let a caller name the holder"), here contained only by the `SELF` guard and by the selector's absence from the diamond cut.
- **Impact class:** Conformance / recurrence risk. If any future facet or package cut exported `executeNamedHolderRedemption`, an external caller could name an arbitrary holder for the burn. That exposure does not exist in the tree I read; the deviation from the prescribed path does.
- **Fix direction:** Replace `_settleNamedHolder`'s delegatecall with a direct internal call to the inherited `_executeZapOutExactIn(tokenOut_, shares_, minimum_, receiver_, holder_)`, mirroring the V3 FullSpread target, and remove `executeNamedHolderRedemption` from the delegate. If EIP-170 was the reason for the delegate form, the plan's instruction is to report the size, not to move the yield path onto a delegate.
- **Confidence:** High on the code facts and on the plan's text; medium that no document I did not read (e.g., `FIX_PRD.plan.md`) amends this.
- **Observed fact vs inference:** Fact — the delegatecall and the new entrypoint exist as cited; V3 uses an internal call. Inference — that EIP-170 pressure motivated the shape (the delegate comment at `UniswapV4StandardExchangeInExecutionDelegate.sol:12` says the SY entrypoint "names its holder before delegation"; no size rationale is recorded there).

- **Remediation ID:** RC-01 (plan Step 2).
- **Intended behavior (controlling text):** "The direct yield path must keep the protections the external `exchangeIn` used to supply: the reentrancy lock, the disable check, and the post-settlement TWAP update. Do not re-enter `exchangeIn` to obtain them."

- **Impact class:** Authorization/availability semantics on a disabled vault.
- **Fix direction:** Add `_requireNotDisabled()` (or the documented current equivalent) to the legacy V4 direct yield path, or obtain and record an owner ruling that legacy V4 SY redemptions are intentionally allowed while disabled, matching the FullSpread product rule.
- **Confidence:** High on the code fact; the plan sentence is explicit. V3 FullSpread is not cited: its public `exchangeIn` deliberately skips the disable check for share routes (`UniswapV3FullSpreadStandardExchangeVaultInTarget.sol:41`) and plan Step 4 names only the reentrancy lock for V3.
- **Observed fact vs inference:** Fact — absence of the check in the cited function. Inference — that this is an omission rather than a recorded owner decision, since no supplied document records one.
