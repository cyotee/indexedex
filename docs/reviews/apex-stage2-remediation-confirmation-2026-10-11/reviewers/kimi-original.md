## Findings

### K3-01 — Legacy Uniswap V4 internal-balance SY redemption still uses the withdrawn external self-call

- **Severity:** Medium. **Class:** CODE_DEFECT (failed execution of a named remediation, RC-01). **Confidence:** high in the control-flow facts; no runtime execution performed.
- **File and line:** `contracts/protocols/dexes/uniswap/v4/UniswapV4StandardExchangeOutMultiQueryTarget.sol:17-25` (and its `_standardRoute` override at :27-35); retained acceptance branch at `contracts/protocols/dexes/uniswap/v4/UniswapV4StandardExchangeCommon.sol:1299-1305`.
- **Intended behavior (FIX_PRD RC-01, the later correcting specification):** internal-balance redemption burns `address(this)` through an explicit-holder internal/library settlement; "Do not re-enter `exchangeIn` to obtain a different `msg.sender`"; acceptance criterion: "No in-scope internal-balance redemption reaches `exchangeIn` through `address(this).call`." FIX_PRD.plan.md Step 5 expressly includes "Legacy V4 out-query targets that inherit it. Fix their internal-balance call shape here. Do not turn this step into an accounting repair, and do not delete the old V4 package."
- **Observed (fact):** the legacy V4 `_redeemVaultHeld` still calls `IStandardExchangeIn(address(this)).exchangeIn(..., false, ...)` — an external call to the same diamond whose `msg.sender` becomes the vault — and the legacy Common still contains the `msg.sender == address(this) && !pretransferred` branch that credits vault-held shares to that forged caller identity (:1302-1305). The earlier `NativeStandardYieldContextRepo` initiator tracking is deleted from production source (bounded grep over `contracts/`), so this branch now has no initiator/context check at all; its only gate is that `msg.sender` is the vault itself.
- **Mitigating facts (why not High/Critical):** the shared `NativeStandardYieldTarget.redeem` entry now rejects a code-less caller with `EOAPretransferNotAllowed()` before any burn (`NativeStandardYieldTarget.sol:41-44`) and requires the vault to actually hold the shares (`:75-78`), so the original unauthenticated-redemption exposure is closed at the entry even for this family. No third-party wallet burn is implied. The remaining defect is retention of the withdrawn mechanism (forged `msg.sender` settlement) on a package still deployed by launch scripts (`scripts/foundry/anvil_robinhood_testnet` Phase 05 Stage 03 deploys the legacy V4 SE package per its README table).
- **Broken requirement/invariant:** FIX_PRD RC-01 required repairs 1–3 and acceptance bullet 1, applied to the legacy V4 family the plan names in scope.
- **Impact class:** conformance/defense-in-depth. One family not closing undermines the "inventory every inheritor" acceptance criterion; no demonstrated loss.
- **Fix direction (prose):** convert the legacy V4 internal-balance path to the same explicit-holder settlement shape used by the other families (burn `address(this)` without re-entering `exchangeIn` through a self-call), and remove or gate the self-call acceptance branch in the legacy V4 share-delivery helper, without touching its accounting rules or deleting the package (the plan forbids both).
- **Attribution of status:** failed execution of RC-01 for this family; not a new defect introduced by the repair.
