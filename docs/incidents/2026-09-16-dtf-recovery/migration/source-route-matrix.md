## Exact schema and conversion boundaries

- W-N `positionOf(uint256)` returns `(principal,claimedPrincipal,stakingGons,startTimestamp,vestingDuration)`; E-N `getPosition(uint256)` returns `(originalShares,effectiveShares,bonusMultiplier,unlockTime,rewardDebt)`, all uint256. Both ownership reads return one address. The deployed safe-transfer route calls the receiver before changing ownership/checking approval; actual missing-approval rollback is in the current source suite. W-N uses fixed principal minus claimed principal. E-N uses original accounting shares, never effective weight or physical LP.
- W-R synchronizes WD before both custody baselines. `n` native9 transfers `n*k` gons; both endpoint gon deltas and unchanged `k` must agree. Sub-native gons and new role allocations remain unbooked. WD `synchronizeRewards()` is selector `0x0910d5ea`, facet `0xd2cda1f88e1f26214419f98ce845f9b4bb06c094`, hash `0x0a55985cd3e4e133f35592213e47872cbaf8105b874e0dd740521cb8d85e46f4`; it is a parent call, not a W-R selector.
- E-R displays `floor(I*r/1e27)` and exposes `sharesOf=floor(I/1e9)`. Native18 transfer `n` moves `floor(n*1e27/rTransfer)` internal shares. Public endpoint-floor intervals plus singleton rate inversion validate that intervening rate. No public exact internal-share getter is assumed; diagnostic storage reads in old witnesses are not a production primitive. NFT-sale external shares E plus remainder R and standalone B conserve `E*1e9+R+B`, with `R<1e9`.
- SY is native9 static shares. Direct claim-vault rights are native19 shares returning measured native9 SY through `redeem(uint256,address,address)`. W-SD is native28 shares returning measured native18 DTF through that same signature on a different source. There is no common decimal divisor or current-source-equivalence assumption. Their actual source-native custody quantities determine credit consumption.
- TokenStaking has native18 accounting weights, phase 2 at the pin, and absent approve/transferFrom routes. `withdrawClaim(uint256)` consumes the caller weight and pays that caller through the fixed vault/SY chain. Prepared original/remaining weight and measured descendant SY are separate quantities. Earlier raw-weight consumption cannot be rolled back by a later failed SY surrender. Exact claim transaction/caller/weight/output evidence and duplicate-original exclusion remain required.
- All legacy `exchangeIn(address,uint256,address,uint256,address,bool,uint256)` routes indexed here return **one uint256**. Do not decode the current two-output interface. Earlier ED recovery targets **E-P with ED as input**, not the previously failing ED primary-burn path.
