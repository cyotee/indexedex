## Summary

When this work is done, the current Uniswap V3/V4 Standard Exchange V2 trees under `contracts/vaults/standard/exchange/protocols/uniswap/v3` and `v4` have been renamed in place to **UniswapV3FullSpreadStandardExchangeVault** and **UniswapV4FullSpreadStandardExchangeVault**. Every component, CREATE3 salt, TestBase, and test in those trees uses the new names. Preserved packages under `contracts/protocols/dexes/uniswap/v3` and `v4` stay byte-identical and are not deprecated here.

**APEX 2026-09-17 amendment (D9, D15, D17, D28).** Public `pretransferred=true` is for integrating contracts only; a code-less EOA reverts `EOAPretransferNotAllowed()`. Exact-input pretransfer credits exactly the requested `amountIn` when unbooked available covers it, leaves excess uncredited, and refunds nothing (D28; FullSpread D19 exact-in push equality is replaced). `pretransferred=false` exact-output pulls quoted `used` and refunds nothing: dual-exit burns `sharesToBurn` not `maxAmountIn`; V3 token exact-out pulls quoted `used` not `quotedIn + quotedIn/1000 + 1`; V4 token exact-out pulls quoted `used` not `maxAmountIn`. Unused pulled value is booked, never refunded, on `pretransferred=false`. Booked `reserveOfToken` is never paid out.

Push is the existing `pretransferred` flag plus `IBasicVault.reserveOfToken`: the last booked ERC-20 balance **on this diamond**. After every vault operation that moves those tokens, `_syncVaultReserves` writes `reserveOfToken[token] = token.balanceOf(vault)`. It is never free + deployed, never inferred from pool liquidity, and never a stored snapshot of position amounts. `localReserve` is the live sleeve (`balanceOf` now). `deployedReserve()` is a live read of the current position, not storage. Share mint/burn still prices against live free + live deployed + live uncollected position fees computed on that call. TWAP stays on the oracle. `preparePretransfer` is not part of the caller sequence and is not on the FullSpread public surface.

The remaining leak classes from the 2026-09-16 review still close: dust first-mint share inflation, no Position Manager Permit2 leftover (the imported-increase helper is removed), and greppable adversarial catalog tests (including fee-on-transfer as a configured pool token). A router `transferFrom`s the user straight to the vault, then calls `exchangeIn(..., pretransferred=true)` with `recipient = user`. Permissionless sleeve rebalance stays public and cannot pay the caller. Locked exits succeed when their quoted payout fits the available output-token sleeve; a positive target alone does not guarantee that capacity. No live vault is upgraded or repointed.

For FullSpread, this PRD supersedes conflicting preparation, reserve-booking, first-mint, naming, and SY-delivery requirements in `UNISWAP_V3_V4_STANDARD_EXCHANGE_REMEDIATION_PRD.md`, `v3/UNISWAP_V3_STANDARD_EXCHANGE_REMEDIATION_PRD.md`, and `v4/UNISWAP_V4_STANDARD_EXCHANGE_CONSTANT_PRODUCT_ACCOUNTING_PRD.md`. Their other economics and release requirements continue to apply. Paths in this document are repository-relative unless explicitly relative to this PRD's directory.

The separate [CREATE3 release salt input correction](../../../../../../docs/create3-release-salt-input-correction.md) owns changes to `ArtifactCreationCode.releaseSalt`, automatic library salts, and contract deployment salts through the CREATE3 Factory across FactoryServices and scripts. It excludes proxy deployment, `PkgArgs`, and `calcSalt`. Complete and record this FullSpread effort's preservation/validation evidence before that separate correction. The requirement to keep shared helpers and preserved sources unchanged below is scoped to this FullSpread effort; it does not prohibit the separately authorized component-salt correction.

## Push delivery (D2)

`pretransferred=true` means the tokens are already on the vault. The before-image is `reserveOfToken`, the last booked ERC-20 balance on this diamond, already exposed as `IBasicVault.reserveOfToken`.

```
actualIn = token.balanceOf(vault) - reserveOfToken(token)
```

That is the shared I1 formula (`U = balanceOf - reserveOfToken`). A second `preparePretransfer` call is not required and is not on FullSpread.

`exchangeIn` is exact-in: unbooked available must cover `amountIn` or the call reverts `TransferDeltaInsufficient`. Credit exactly `amountIn`. Extra unbooked above `amountIn` is not refunded and does not revert (D28). Public `pretransferred=true` is contract-only; EOA reverts `EOAPretransferNotAllowed()`. `exchangeOut` is exact-out: credit `min(unbooked, maxAmountIn)` and refund only `credit - used` to `msg.sender` on true-flag. False-flag pulls quoted `used` and refunds nothing (D15/D17). Fat max plus transfer of only `used` succeeds on true-flag. Catalog E6 protects booked reserves.

`_syncVaultReserves` writes `reserveOfToken[token] = token.balanceOf(vault)` only when the vault moves diamond ERC-20: deposit, withdraw, rebalance, collect, vault swap, wrap/unwrap, import. External Uniswap trades change live position amounts, not `balanceOf(vault)` and not `reserveOfToken`. Uncollected V4 fees sit in the PoolManager until collect, which is a vault function that then writes `reserveOfToken`. A stray `transfer` onto a live vault is the donor's loss; it is not an LP principal exploit.

`localReserve` is the live sleeve. `deployedReserve()` is a live position read. Neither is stored as the push before-image. Do not persist deployed amounts. Share mint/burn still prices against live free + live deployed + live uncollected position fees computed on that call. TWAP is the oracle.

The auditor P0 was writing free + deployed into `reserveOfToken`, then treating delivery as if booked local inventory included the pool. After a pool trade that number was wrong, so a false `pretransferred=true` minted from inventory already in the book. Writing `reserveOfToken` from `balanceOf` after vault ops closes that. A pool trade then an unfunded `pretransferred=true` must revert (`test_L1`).

Router path: `transferFrom(user, vault, amount)` then `exchangeIn(..., amount, ..., recipient=user, pretransferred=true)`. The vault does not see the ERC-20 sender. It credits `balanceOf - reserveOfToken`. A router with `transferFrom` rights can already move the user's tokens. `recipient` is an `exchangeIn` argument the user must trust the router to set.

External Native SY share redeem uses `exchangeIn` after transferring shares onto the vault, so `actualIn` must equal `amount_`. Internal SY redeem uses `super._standardRoute` (fixed proxy self-call, `pretransferred=false`). Delivery credits the diamond's existing share balance; the existing zap-out/execute burn is the only burn. It neither `transferFrom`s shares from itself nor treats already-booked self-shares as new delivery.
