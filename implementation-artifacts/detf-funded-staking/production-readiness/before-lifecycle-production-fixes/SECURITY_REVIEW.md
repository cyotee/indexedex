# Internal production-path security review

Scope: unified V4 DETF CP, Weighted, Orbital and Curve Quad; shared funded bond/staking/SY components and retained SE dependencies. This is an internal source review supported by deployed-proxy tests, not an independent external audit. Runtime acceptance remains pending until the matching final validation and strict rehearsal complete.

## Findings

`security-findings.json` preserves reproduction and disposition for PR-01 (positive burn with zero final payout), PR-02 (payable boundary blocked by unmintable DETF self-leg) and PR-03 (local runner evidence overwrite). The first two change `UniswapV4DetfTarget.sol`; they do not change ABI, storage, thresholds, allocation or NFT vesting semantics. Before/after traces and direct boundary regressions are retained separately.

Primary burns measure protocol-owned LP against supply after required epoch settlement. Positive LP alone was insufficient: the final recipient asset can round to zero. The production guard now runs after final conversion and the existing user minimum check, before cleanup. Any revert restores input, LP, nested provider state, staking backing and bond state. Reserve-swap final output has the same guard, including conversions after acquiring the native pair token. The CP hook can reject an unpayable pair amount earlier with its own `ZeroAmount()`; the direct fallback regression retains that error rather than swallowing it.

A self-leg whose actual single-asset join preview is zero remains protocol inventory and passes to the existing bounded residual sweep. It creates no user entitlement and is not burned. Nonzero-quote join errors still propagate. The direct first-payable regression, separately from the fuzz domain, protects this case.

PR-04 is a high-severity deployment-core authorization defect: the two canonical facet override entrypoints and canonical package replacement did not require an authorized caller. The installed Robinhood core accepted both facet override calls and the canonical package setter from an arbitrary address in read-only `eth_call` simulations at block 56,118,361. The setter probe independently verifies that the caller is neither owner, global operator nor function operator; its public mapping remains unchanged after simulation. No transaction was sent. An attacker could replace canonical dependencies or occupy deterministic salts before an authorized deployment. The three mutators now use Crane's existing `onlyOwnerOrOperator` guard; no signature or storage layout changes. The new production-factory regressions cover unauthorized atomicity, owner/global/function operators and revocation with constructive bounded callers. All eight authorization regressions passed against the corrected complete build. The fresh local core now passes all three unauthorized-call probes with the exact NotOperator error; runtime, owner/operator wiring and registered packages reconcile to current artifacts. The pinned vulnerable public core must not be reused as this release's core. The rehearsal deployed a fresh corrected factory and registry chain.

This dependency change invalidates the previously matched provider-fork closures. Their original passes are preserved as historical evidence; their current closures were renewed after the corrected build. The pre-fix compile finished successfully in 15,790.852 seconds. Its sequence rejected that superseded source snapshot before running tests. The corrected complete build passed in 27,719.527 seconds and all 27 security/boundary regressions passed. The matching full hermetic suite passed all 31,305 tests with zero failures/skips; all 27 provider fork cases and all eight retained V3 cases also pass against the same candidate. Strict local validation remains required for release.

PR-05 isolates Phase 09 address exports through `FRONTEND_ADDRESS_EXPORT_DIR`; local validation must not publish fork addresses or replace the application's existing product lists. PR-06 corrects the funding simulation's omitted Balancer hook catalog stage and its hard-coded broadcast-artifact path. The quote now honors an isolated absolute or relative directory and rejects empty or incomplete gas records. Eight deterministic checks pass and the simulation's 19 stages match the maintained deployment catalog in order. The full local deployment/export completed and preserved application bindings; the funding simulation remains pending.

PR-07 corrects the staged launch wrapper so local simulation and broadcast use the same legacy fee mode. The first strict local attempt failed before broadcasting because simulation requested unavailable future fork fee metadata. Its log and empty deployment transaction state are archived. Six command-builder cases preserve default public EIP-1559 behavior and EIP-1559 funding quotes while checking local staged parity. The corrected local deployment and all 156 receipts pass. The full funding quote remains pending; no public transaction was sent.

PR-08 populates the mandatory exit/query facet addresses omitted by the maintained Balancer stable hook launch library. The package correctly rejected its zero fields during stage simulation, before that stage broadcast. Both facets now deploy through the existing production FactoryService; constructor checks stay intact. The changed launch library and two script entrypoints compiled in the complete normal build (132.233 seconds). Production/test/dependency/compiler inputs are unchanged, so the recorded execution source closures are reused explicitly. All local stages, including the corrected final stage, now have successful receipts. The complete aggregate funding simulation remains pending.

## Initialization, storage and callers

`storage-review.json` records all 59 current top-level funded/Table fields and five nested BondPosition fields. It explicitly covers tuple writes, mutating AddressSet accessors, route-table storage aliases, and memory-only preview/salt mutations. Current namespaces are distinct; no legacy LP-valued storage is reinterpreted as funded state. Existing position-field removal maps remain linked from the parent artifacts.

The V4 package requires canonical ABI encoding, registry-only argument processing, exactly one DETF self-leg, matching hook ownership/liquidity policy and validated rates/routes. Children deploy through the configured package registry and reject duplicate initialization. Product proxy cuts contain the supported role facets; retired LP claim/close selectors are checked through real proxies. Deployed DETF instances expose no upgrade or owner pause route.

The current frontend check passes lint, typecheck and 410 tests. Twenty-eight supported deployment, exchange, bond, NFT and staking ABI declarations match compiled production artifacts (`frontend-abi-reconciliation.json`). Optional historical display getters have explicit current-route fallbacks. The production fixes add no selector or deployment argument; minimum-output and operator errors already exist in the ABI. No frontend network/address binding has changed. The local package manifests are recorded independently. Actual runtime inspection covers 306 component records, including recursive linked-library code, package-hosted initialization facets, explicit funded NFT transfer replacements and current platform configuration. All 135 CREATE3 calls have independently matched inputs and address calculations.

The launch export’s WETH and PONS metadata was checked through read-only calls on the strict local fork at Robinhood block 56,118,361. Both actual tokens use 18 decimals, matching the export (`native-export-token-preflight.json`). This does not substitute for native-unit checks on deployed SE/DETF/SY instances. `frontend-live-check-scope.json` records why the conditional browser-transaction gate is not triggered by isolated architecture exports; no new browser money-path pass is claimed.

## Explicit scope dispositions

D60 excludes Balancer-hosted DETFs. The earlier H9 conservation change bounded a payable test domain; it did not fix excluded production redemption code. Those products must not enter this release candidate. Balancer SE and V4 Balancer hook packages remain in scope. D66 defers unfinished Slipstream; no new release claim is made for it. User-provided arbitrary or malicious underlying tokens are not introduced as newly supported assets by this review.

Passing finite tests does not establish a universal proof of economic safety, arithmetic bounds or external protocol behavior. Any remaining failed required check remains an open acceptance item, not a waived finding.

## Validation-tool corrections

The first runtime inspector stopped on compiler link placeholders, abstract initialization-mixin names and intentionally replaced ERC721 transfer selectors. It now recursively verifies each linked library against current source/runtime, validates the library self-address guard, compares package-hosted facets to their containing package, and accepts only the three source-declared NFT replacements after a prior Add. Duplicate additions, repeated selectors inside one cut, missing replacements, altered runtime, stale sources and invalid links remain failures. Eight independent verifier regressions pass; the actual deployment check passes. These were verification-tool limitations, not altered contract acceptance semantics.

The initial lifecycle attempt failed compilation before executing cases because a referenced interface was not included in its named import. The import correction retains every assertion, 39-case scope and 30M transaction bound. The full lifecycle must execute; the failed attempt is preserved. Both narrow source-closure bridges preserve original passing production/hermetic/provider evidence without relabeling it as rerun evidence.
