# V4 reserve policy and LP bond API changes

Applies to new deployments of the four unified V4 DETF bindings. Balancer-hosted DETFs remain excluded from functional refactoring.

- `IUniswapV4Detf.PkgArgs` adds `bool ownerOnlyLiquidity` immediately after `hook`. Frontend ABI encoding and all deployment/premine helpers must use this exact layout. Changing the policy changes the predicted DETF and hook addresses. Select it before prediction/mining.
- Both processArgs and account initialization validate the actual hook policy. Older hooks without the policy getter are not silently assigned an assumed policy. The DETF remains the hook owner in both modes.
- `ownerOnlyLiquidity()` is a read-only hook and DETF view; there is no toggle.
- In restricted mode, additions require DETF. Removals require DETF or the live oracle `feeTo()` Fee Collector; normal LP ownership/allowance checks still apply. A former collector may transfer residual LP to the new collector but does not keep special withdrawal authority. This does not move the standing staking-reward NFT beneficiary.
- `IFeeCollectorManager.redeemReserveLiquidity(reserveLp, amount, amountsMin, recipient, deadline)` is collector-owner operated and uses proportional redemption of collector-held LP. Its selector is installed by the existing collector manager facet. Existing collector instances would need their normal owner-authorized upgrade before using this new operation; no such live upgrade is part of this task.
- `previewBond(tokenIn, amountIn, lockDuration)` returns purchased DETF, vested principal, staking reward funding, and newly issued liquidity DETF. Amounts are native nine-decimal DETF units. The own-reserve LP path returns zero newly issued liquidity DETF. Its per-leg duration-adjusted quotes all use the same pre-payment reserve snapshot, then the funded split is applied to the aggregate purchased quote.
- `acceptedBondTokens()` includes the own reserve LP only after activation. The first bond remains the existing initial-asset process.
- LP payments use transferFrom with actual balance verification; a caller cannot claim already-held LP through a pretransfer flag. The complete LP remains in protocol custody, while only its non-DETF proportional entitlements determine purchased principal.

Implementation and validation remain in progress. The creation policy and live LP-preview frontend checks pass (410 tests, lint and typecheck); Solidity production-path validation and full-repository checks remain required.

## Position-vault and quote compatibility follow-up

V3/V4 standard `previewExchangeIn` remains installed at the same selector; its implementation now resides on the existing InMultiQueryFacet so the transition query and standard route facets each fit EIP-170. V4 OutFacet calls its installed preview selector instead of embedding another quoter. This relocation changes no caller ABI.

V4 initial activation requires both asset legs. Importing an approved NPM NFT now collects its principal and fees, accounts for actual received assets, and installs the managed full-range center before minting shares. The old empty NFT remains in custody as metadata. Existing sleeve inventory cannot be acquired by the importer. V4 native SY uses existing 18-decimal shares, liquidity metadata and the complete asset book; no ERC-20 yield token is fabricated.

`IStandardExchangeTransitionQuote.Operation.ReceiveShares` is appended as enum value 3. It projects an existing share transfer into the selected holder's inventory. It does not mint shares, collect fees, rebalance, or change underlying backing. The existing enum values and selectors stay unchanged. Current repository ERC4626, V2, V3, V4 and Morpho implementations support this operation. A third-party implementation of the earlier optional quote interface may not support value 3; deployment/integration validation must check this before using a share-input sequential route with that implementation. This read-only operation never supplies transfer authorization for execution.

Orbital's `previewBurnToToken` remains its retained proportional reserve valuation. The native SY single-token redemption uses `previewExitSingleAssetExactBptIn`, which projects the actual proportional withdrawal and residual swaps. Reserve valuation and an executable one-token exit are different operations; the former must not acquire the latter's trade-size liquidity dependency. SE-share deposit previews include the received-share redemption before quoting the existing Orbital zap.

The native SY `burnFromInternalBalance=true` path records the initiating caller only for the duration of its internal self-call. Restricted V4 hooks use that initiating caller for removal permission, checking the live fee oracle each time. This adds no public removal right, no addition exception, and no permission to burn another holder's LP. Execution still burns only the specified amount of shares held by the SY itself. The caller context clears after the call and reverts atomically on failure. The four-family/two-policy collector-rotation cases and three restricted caller-context suites pass in `v4-native-sy-and-collector-300-green-*`.

Single-buffer CP native SY now advertises its existing SE-share deposit route in addition to raw and pair inputs. Its output discovery stays raw/pair because an SE-share single-output exit is not supported by that hook. The share-input preview projects receipt and redemption through the underlying SE, then the existing pair-side zap and proportional join, retaining the hook's pre-receipt protocol-fee ordering. No standard signature or exact-output capability changes. The three supported input routes pass in `v4-native-sy-and-collector-300-green-*`.


V4 native SY selectors now reside on the existing OutMultiQueryFacet; the standard single-output preview remains on OutQueryFacet. Proxy signatures, ERC165 support, metadata and money routes are unchanged. The shared V4 inventory snapshot supplies both transition and standard withdrawal queries. Its exact minimum search permits eight bounded interpolation probes before binary fallback and retains the existing share buffer. The execution delegate verifies a budget hint against adjacent installed exact-input quotes, then uses the installed exact-output preview if the hint is not the exact standard budget. Exact share approvals and excess/prepaid refunds are preserved. All 43 focused money-path/size checks pass in `v4-cached-exact-withdrawal-43-green-*`; the subsequent 340-test broad selector/regression selection also passes (`v4-cached-withdrawal-and-collector-340-green-*`).
